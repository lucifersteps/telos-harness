# 微信主动消息收尾提醒

微信没有返回可查询的剩余额度。按本机观察到的每次新入站消息后 10 个气泡作保守预算，不把它描述为微信官方保证。普通回复、主动消息、定时输出、图片和图片说明都消耗预算。

复用 business.sqlite 的 facts 保存最后一次真实入站消息 ID 和当时累计投递基线；消耗量来自现有 text_outbox、schedule_outbox、image_receipts，不新增表、事件状态或计时器。重复入站、重启、定时唤醒不重置基线。未跟踪的旧安装从下一条真实入站开始计算；本次本机升级依据已有脱敏回执迁移当前窗口。

剩余预算不超过 2 且大于 0 时，当前主动事件改成一个收尾提醒，替代整组观察和建议。模型只生成最多 180 字的 message，不查询行为、健康、设备或计划，也不补缺失说明。模型看到最近三次已发送的收尾提醒；完全相同的文案会要求改写。语气可以撒娇，但不能责备或威胁永久离开；说明“快用完了”、暂时安静、微信回复一句即可恢复。

事件 detail 标记这次入站对应的收尾提醒，原来的 queued/sent/unknown 状态负责防重和发送结果。同一窗口不再批准其他主动事件。预算为 0 时不再尝试发提醒。收到新消息会取消未发出的旧收尾提醒，恢复下一次原定主动检查；不修改用户暂停设置，不创建额外检查任务。

待发 outbox 提前预留气泡；发送前再校验，预算变化时取消尚未发出首段的普通消息组。已确认的前缀不重发，明确拒收复用原有重试，未知回执不自动重放。未知回执按可能已花费计算，但新入站基线会吸收旧未知回执，避免永久占用新窗口。
